# CRAVE backend — Railway's actual build entry point.
#
# This file is deliberately self-contained again, duplicating
# backend/requirements.txt's package list, after two separate attempts
# tonight to eliminate the duplication via Railpack customization each
# broke production in a different way:
#
#   1. Collapsing this file to `-r backend/requirements.txt` broke the
#      build: Railway's Railpack builder auto-detects Python and, as a
#      caching optimization, copies ONLY this top-level file into the
#      build context before running `pip install -r requirements.txt` —
#      it never resolves `-r` references to other files first, so pip
#      couldn't find backend/requirements.txt (not copied in yet).
#   2. Replacing that with a custom railpack.json pinning the real
#      install command explicitly (`pip install -r backend/requirements.txt`)
#      broke a different way: a custom step's `inputs` field defaults to
#      nothing, not "the local repo" — so the install step ran against a
#      filesystem with no source files in it at all.
#   3. Adding `"inputs": [{"local": true}]` to fix #2 hit a THIRD failure:
#      Railpack rejected it outright ("`install` inputs must be an image
#      or step input") — a bare local-files layer isn't a valid sole
#      input for a step with nothing else to build from.
#
# Three failed attempts in one night to make Railpack's custom step model
# do something Railway's own zero-config Python auto-detection already
# does correctly by default — which only works when it can see a
# self-contained requirements.txt at the repo root, no `-r` indirection
# for its file-copy heuristic to miss. So: back to duplication, but with
# the actual class of bug (two copies silently drifting apart, which is
# what caused the ORIGINAL sentry-sdk/playwright/pdfminer gaps) closed a
# different way — see the "Root requirements.txt matches backend's" CI
# step in .github/workflows/ci.yml, which fails the build if this file's
# package list and backend/requirements.txt's ever diverge. Edit
# backend/requirements.txt first, then copy its package lines here
# verbatim; CI is the thing that actually enforces they stay identical
# now, not a comment asking a human to remember.
