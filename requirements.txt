# CRAVE backend — Railway build entry point.
#
# Railway's build runs `pip install -r requirements.txt` from the repo
# root (before `cd backend` in the deploy start command — see
# railway.toml), so THIS file, not backend/requirements.txt, is what
# actually gets installed into the deployed container.
#
# This used to duplicate backend/requirements.txt's full contents with a
# comment instructing whoever edits one to also edit the other by hand.
# That already drifted out of sync twice: first missing pyjwt/redis/boto3
# and carrying an impossible "starlette>=1.0.0" constraint, then missing
# playwright/pdfminer.six/sentry-sdk after a later pass added them to
# backend/requirements.txt only. The second drift was worse than the
# first — sentry-sdk is imported unguarded at module level in
# app/main.py the moment SENTRY_DSN is set, so that specific gap wasn't
# a silently-degraded feature like the other two, it was a total prod
# outage waiting for someone to configure error monitoring, which is
# the natural next step main.py's own comment invites.
#
# Neither drift was ever visible in CI: ci.yml only ever installs
# backend/requirements-dev.txt from the backend/ working directory,
# never this file, so nothing exercises the exact dependency set Railway
# actually deploys with.
#
# A single line eliminates the class of bug rather than re-fixing today's
# instance of it — there is now nothing here to keep in sync by hand.
-r backend/requirements.txt
